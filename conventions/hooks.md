# 훅 컨벤션

## 1. 목적과 적용 범위

이 문서는 Claude Code 훅을 만들고 고치는 규칙을 정한다.
훅은 Claude Code가 정해진 시점에 실행하는 스크립트다. 규칙을 코드로 검사해서 작업을 막거나 통과시킨다.
에이전트는 훅을 만든다. 사람은 무엇을 막을지 정하고, 만든 훅을 확인한다.

## 2. 훅으로 만들 규칙

- **HK1. 다음 조건을 모두 만족하는 규칙만 훅으로 만든다.**
  1. 코드로 판단할 수 있다. 파일 경로, 명령 문자열, 메시지 형식이 그 예다.
  2. 컨벤션 문서에 이미 적혀 있다.
  3. 문서로 안내했는데도 반복해서 어겼거나, 어기면 피해가 크다.
- **HK2. 뜻을 이해해야 판단할 수 있는 규칙은 훅으로 만들지 않는다.** 답변 문체가 그 예다.
- **HK3. 사용자가 요청하거나 승인한 규칙만 훅으로 만든다.** 에이전트는 후보를 제안할 수 있다.
  제안할 때는 어긴 사례와 막을 방법을 함께 쓴다.

## 3. 만드는 방법

- **HK4. 훅 하나는 규칙 하나만 검사한다.**
- **HK5. 스크립트는 Python 표준 라이브러리만으로 쓴다.** 따로 설치할 것이 없게 하기 위해서다.
- **HK6. 스크립트는 프로젝트의 `.claude/hooks/`에 두고, `.claude/settings.json`에 등록한다.**
  두 파일 모두 커밋한다. 그래야 같은 프로젝트의 모든 세션에 적용된다.
- **HK7. 검사 대상을 좁힌다.** `matcher`로 도구를 고르고, 스크립트 안에서 명령이나 경로를 다시 확인한다.
  관계없는 작업은 바로 통과시킨다.
- **HK8. 막을 때는 종료 코드 2로 끝내고, 이유를 표준 오류에 쓴다.**
  에이전트는 이 이유를 읽고 작업을 고친다. 그래서 이유에는 어긴 규칙, 근거 문서, 고치는 방법을 모두 쓴다.
  예: "커밋 메시지는 `feat:` 같은 유형으로 시작해야 한다(`conventions/git.md`). 메시지를 고쳐 다시 커밋한다."
- **HK9. 스크립트 자체가 예상하지 못한 오류로 실패하면 작업을 통과시킨다.** 오류 내용은 표준 오류에 남긴다.
  보안 훅은 예외다. 보안 훅은 판단할 수 없으면 막는다.
- **HK10. 스크립트 첫머리 주석에 검사하는 규칙과 근거 문서를 적는다.**

## 4. 검증

- **HK11. 등록하기 전에 다음 세 가지를 확인한다.**
  1. 규칙을 어긴 입력이 막히는가
  2. 규칙을 지킨 입력이 통과하는가
  3. 관계없는 도구 사용이 통과하는가
- **HK12. 확인할 때는 훅이 받는 JSON을 표준 입력으로 넣고 종료 코드를 본다.**

  ```bash
  echo '{"tool_name":"Bash","tool_input":{"command":"git commit -m \"wip\""}}' | python .claude/hooks/check-commit.py; echo $?
  ```

- **HK13. 확인한 입력과 결과를 사용자에게 보고한다.**

## 5. 우회 금지

- **HK14. 에이전트는 훅에 막혔을 때 훅을 고쳐서 우회하지 않는다.** 막힌 이유대로 작업을 고친다.
  훅 스크립트, `.claude/settings.json`, `.claude/settings.local.json`이 모두 여기에 해당한다.
- **HK15. 다른 도구로 같은 작업을 돌아가지 않는다.** 예를 들어 Edit가 막히면 Bash로 같은 파일을 쓰지 않는다.
- **HK16. 훅이 잘못 막는다고 판단되면 작업을 멈추고 사용자에게 알린다.** 훅은 사용자가 승인한 뒤에 고친다.
